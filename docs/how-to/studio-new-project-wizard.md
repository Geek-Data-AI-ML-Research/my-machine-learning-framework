# Start a Studio project with the DS playbook wizard

How-to. Create a Campaign SaaS project so the first roadmap is EDA → validation → dumb baseline → features — never “pick GPT first.”

## When to use this

- You opened Studio after `make up` and need a real campaign (not only Demo).
- You want Kaggle and commercial projects to share the same first ~60% of process, then diverge.

## Open the wizard

1. Start the stack: [Run the Campaign SaaS stack](run-campaign-saas.md).
2. Open Studio (`http://127.0.0.1:5175/` or the host port you use).
3. Sign in / register (Compose sets GitHub OAuth stub for local).
4. Click **New project** → route `#studio/new`.

## Steps (in order)

| Step | You choose | Why |
| --- | --- | --- |
| **Venue** | Name + Commercial / standalone **or** Kaggle | Same early loop; last 40% goals differ (ROI/latency vs LB squeeze). |
| **Data** | Tabular · Text · Vision · Sequential | Sets the *recommended* baseline family only — still no heavy model yet. |
| **CV** | StratifiedKFold · Time+group · GroupKFold | Leak-free yardstick before any feature or model claim. Venue suggests a default. |
| **Baseline** | LightGBM / Logistic / XGB / CatBoost + goal threshold | 15–60s CPU baseline and importance leak alarm — not a neural net. |
| **Strategies** | Modality ladder + optional paradigm shifts | Same catalog as `python -m mymlfw playbook` / `GET /v1/playbook/catalog`; tick shifts that may apply later. |
| **Links** | Kaggle slug (required if Kaggle) · optional git | Tokens stay in Settings / Kaggle — not in the project name. |
| **Create** | Review + optional roadmap seed | Writes the project, then seeds playbook artifacts. |

The sticky **Expert coach** panel restates the rule for the current step.

## CLI (same source of truth)

```bash
python -m mymlfw playbook strategies --modality tabular
python -m mymlfw playbook shifts --modality tabular --kind kaggle
python -m mymlfw playbook roadmap --modality tabular --kind kaggle --shift synth_gpt_tabular
python -m mymlfw playbook catalog --modality text --kind standalone
```

Studio loads `GET /v1/playbook/catalog` so the wizard never drifts from the CLI module (`mymlfw.playbook`).

## Modality strategy ladders

Climb only after Stages 1–3 beat on locked CV.

### Structured tabular

| Tier | Strategy |
| --- | --- |
| default | Gradient boosted trees + linear (LightGBM / XGB / CatBoost + Ridge/Logistic) |
| escalate | Diverse tree/linear ensemble + residual stack; FT-Transformer / deep MLP after trees plateau |
| paradigm | GPT-2 / small LM on tokenized rows (synthetic-from-NN tables); TabPFN / prior-fitted nets (small-n) |

### Text / documents

| Tier | Strategy |
| --- | --- |
| default | TF-IDF + Logistic; frozen sentence embeddings + linear |
| escalate | DeBERTa / RoBERTa fine-tune; open-weight LLM / API few-shot |

### Images / video / audio

| Tier | Strategy |
| --- | --- |
| default | Frozen ConvNeXt / ViT + linear or LightGBM head |
| escalate | Fine-tune backbone; detection / segmentation heads when the task needs boxes/masks |
| paradigm | Multimodal late fusion (image + tabular) after unimodal baselines |

### Sequential events

| Tier | Strategy |
| --- | --- |
| default | Rolling-window aggregates + trees |
| escalate | GRU / LSTM; lightweight sequence Transformer |
| paradigm | Survival / Hawkes / point-process when the target is time-to-event |

## Possible paradigm shifts

Opt-in on the **Strategies** step. Studio filters by venue + modality. Each selected shift seeds a **gated** Roadmap item (priority ≥ 60) that must still beat Stage 3 — otherwise dead-end it.

| Shift | Typical when |
| --- | --- |
| Synthetic NN tabular → GPT-2 / token LM | Playground-style tables generated by a neural process |
| Text column dominates → encoder / LLM | Free-text carries most signal |
| Small-n high-p → TabPFN / strong priors | Few rows, wide feature space |
| Label delay / chargeback lag | Commercial positives arrive late (time-aware CV first) |
| Entity leakage → Group / purge CV | Same customer/device leaks across splits |
| Cost-sensitive thresholding | $FN/$FP asymmetry before chasing 0.001 AUC |
| Multimodal late fusion | Image/text + tabular after unimodal baselines |
| Kaggle last 0.1 bps squeeze | Diverse zoo + residual stacking (Kaggle only) |
| Commercial stop rule (1–2 models) | Latency / maintainability / explainability |
| Detection / localization task | Boxes or masks, not global classify |

## What create writes

Uses existing APIs only (no new JSON fields):

1. `POST /v1/projects` — name, kind (`standalone` \| `kaggle`), primary goal, optional `kaggle_competition` / `git_remote`.
2. If **Seed … on Roadmap** is checked (default):
   - `POST /v1/projects/{id}/roadmap` for Stages 1–5 (priorities 10–50): EDA → CV lock → dumb baseline → domain features → Kaggle squeeze **or** commercial deploy path (Stage 5 plan includes the modality ladder);
   - additional roadmap rows for each selected paradigm shift (priorities 60+);
   - one `POST /v1/projects/{id}/progress` note locking venue / modality / CV / baseline / ladder / shifts.
3. Studio navigates to **Roadmap** (planned filter) so the next agent turn starts on Stage 1.

Uncheck the seed box only when you intentionally want an empty roadmap.

## After create

- **Roadmap** — execute Stage 1 before changing Stage 2 folds.
- **Paradigm shifts** — leave planned until Stages 1–3 are executed; if a shift fails to beat Stage 3, record a dead end.
- **Kaggle** projects — sync LB from the Kaggle mode when the API token is sealed ([run-campaign-saas](run-campaign-saas.md#kaggle-sync-optional)).
- **Agents** — mint a PAT and follow [Keep a Studio project updated via MCP](agent-mcp-campaign-sync.md); do not invent a parallel process that skips the seeded stages.

## Anti-patterns

- Starting with a large LLM / vision net / GPT-2-on-tabular before Stages 1–3.
- Treating a paradigm shift as Stage 1.
- Changing CV after Stage 2 without recording a new plan and dead-ending the old split.
- Using Kaggle-style stratified folds on live time-series commercial labels (or the reverse) without documenting why.
